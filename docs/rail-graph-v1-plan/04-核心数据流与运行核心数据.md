# 核心数据流与运行核心数据

## 1. 主数据链（最终跑起来流动的数据）

统一主链：
`SourceInput -> NormalizedEntityBatch -> RailGraph -> RunSpec -> RunPath -> RunOrder -> Timeline -> EventStream -> Diagnostics`

## 2. 各阶段核心数据

### 2.1 SourceInput
- 来源：ORM、OpenRailwayMap、legacy networkMeta、geojson 补充标签。
- 特征：字段可能缺失/不一致。
- 最小字段：`source`, `entityKind`, `rawPayload`。

### 2.2 NormalizedEntityBatch
- 作用：把多源数据拉平到统一实体集。
- 核心内容：
  - `nodes[]`：站、站台、道岔、关键点
  - `edges[]`：股道/区段/方向边
  - `relations[]`：层间关联（站-站台、服务线-基础边）
  - `provenance[]`：来源追踪

### 2.3 RailGraph
- 作用：统一多层图运行基底。
- 核心结构：
  - `infraLayer`: 物理连通
  - `serviceLayer`: 上下行/复线经由/系统语义
  - `runtimeLayer`: 运行计划装配位
- 关键索引：
  - `nodeById`, `edgeById`, `adjacency`, `serviceBindings`

### 2.4 RunSpec
- 作用：描述一次待生成运行计划的输入意图。
- 关键字段：
  - `startRef`, `endRef`
  - `directionHint?`
  - `pathOverride?`
  - `timetableAnchors?`
  - `eventPolicy?`

### 2.5 RunPath
- 作用：图上确定唯一运行路径（可解释）。
- 关键字段：
  - `edgeSequence[]`
  - `nodeSequence[]`
  - `chosenDirection`
  - `candidateScores[]`
  - `resolvedBy: auto|manual`

### 2.6 RunOrder
- 作用：离散顺序骨架，供 timeline/events 共用。
- 关键字段：
  - `orderPoints[]`（顺序号 + 实体引用）
  - `boundaries[]`（关键边界：道岔、系统切换点）

### 2.7 Timeline
- 作用：把顺序骨架转为时间点。
- 关键字段：
  - `timelinePoints[]`:
    - `orderIndex`
    - `timestamp?`
    - `isSynthesized`
    - `sourceAnchorRef?`

### 2.8 EventStream
- 作用：输出有序事件序列（暂不要求最终渲染）。
- 关键字段：
  - `events[]`:
    - `eventId`
    - `eventType`
    - `orderIndex`
    - `timestamp?`
    - `entityRefs`
    - `payload`

### 2.9 Diagnostics
- 作用：贯穿全流程记录补全、冲突、降级与失败。
- 关键字段：
  - `level`, `code`, `stage`, `message`, `context`

## 3. 关键流转规则

### 3.1 顺序先于时间
- `RunOrder` 必须先生成。
- `Timeline` 只在 `RunOrder` 基础上补充时间语义。

### 3.2 事件绑定双锚
- 每条事件必须至少绑定 `orderIndex`。
- 有时间时再绑定 `timestamp`，无时间不阻断事件输出。

### 3.3 路径与事件可追溯
- `RunEvent` 必须能追溯到：
  - 来源边/点
  - 生成规则或输入锚点

### 3.4 缺失补全与诊断并行
- 补全不是隐式行为，必须写入 `Diagnostics`。
- 核心阶段出现 `fatal` 时停止该 run 后续阶段。

## 4. 与现有结构映射
- `TripSegment(lineKey, fromId, toId, loopVia)` -> `RunSpec` 的最小输入子集。
- `networkMeta(common/byDirection/subSegments/events/systems)` -> `serviceLayer` 语义源之一。
- `geo.worker` 几何切片结果 -> `RunPath` 几何表现层附属数据，不作为路径唯一真源。

## 5. 输出给后续实现的最小闭环
最小可运行闭环（不接 UI）：
1. 输入一个 SourceBatch
2. 构建 RailGraph
3. 输入 RunSpec
4. 输出 RunPath + Timeline + EventStream + Diagnostics
5. 导出快照 JSON 供人工校验
