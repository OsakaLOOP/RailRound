# 决策中间件与对外接口草稿

> 路径决策的层级化规则引擎，以及"本地生成→部署→用户使用"全链路的对外抽象。不涉及内部代码结构，只定义决策层级、优先级链和接口边界。

## 1. 决策层级

路径求解不是一步完成的，而是逐层收窄：

```
Layer 1: 系统匹配      — 用户在哪个运行系统里跑？（JR East / Tokyo Metro / ...）
Layer 2: 线路匹配      — 系统的哪条线？（Yamanote / Saikyo / ...）
Layer 3: 方向决策      — 线的哪个方向？（内回り / 外回り / 北行 / ...）
Layer 4: 边界裁切      — 起终点在边序列上的精确起止位置
Layer 5: 站台分配      — 每个站用哪个站台面？（1/2番线 or 3/4番线）
Layer 6: 时刻注入      — 默认时刻表 / 用户指定时刻 / 速度推断
Layer 7: 事件生成      — 从路径 + 时刻投影到事件序列
Layer 8: 渲染输出      — 几何拼接 + 偏移 + 颜色 + landmark 标签
```

每层有独立的输入来源和优先级。

---

## 2. 每层优先级链

### Layer 1 — 系统匹配

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 (最高) | 显式 `systemRef` | 用户指定跑 JR East |
| 2 | ServicePattern 覆盖起终点 | 自动匹配：哪个系统下的 ServicePattern 同时包含起点站和终点站 |
| 3 | 跨系统 transfer | 无单一系统覆盖时，搜索 transfer relation 找跨系统路径 |
| 4 (最低) | 报 `error` 诊断 | 无候选 → 路径不可达 |

### Layer 2 — 线路匹配

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 显式 `lineRef` / `servicePatternRef` | 用户指定跑山手线 |
| 2 | ServicePattern 覆盖起终点（同系统内） | 候选多条时进入 Layer 3 方向比较 |
| 3 | 跨线 transfer | 同一系统内需要换线 |
| 4 | 报 `error` 诊断 | 无候选 |

### Layer 3 — 方向决策

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 显式 `directionHint` | 用户说"内回り" |
| 2 | `viaRefs[]` 约束 | 用户说"必须经过目白" → 方向由 viaRefs 确定 |
| 3 | 前后段方向一致性 | 跨线场景中与前后段方向一致（非环线）/ 环线为单独判定 |
| 4 | 距离比较 | 环线两方向取短、非环线不做此比较 |
| 5 | 默认 | 环线等长时 clockwise；非环线 index 顺序 |

### Layer 4 — 边界裁切

起终点在 ServicePattern.stationSequence 中的精确位置：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | stationSequence 中的精确索引 | 起终点站 ID 匹配 |
| 2 | pathOverride 裁切 | 用户指定在 edge 的某个 measure 处起止（非站点起止） |
| 3 | 报 `error` | 起终点不在任何 ServicePattern 的 stationSequence 中 |

### Layer 5 — 站台分配

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 显式 `platformRef` (在 ServicePattern.stationSequence 中) | 管理后台绑定 |
| 2 | `platformSelectionRule` (ServicePattern 级别) | 自动规则：按方向/到发线角色/距出口距离 等 |
| 3 | 默认推断 | 取 `platform_serves_track` relation 中最近的一个 |
| 4 | 无平台 + 输出 `warn` | 路径仍可生成，站台信息为空 |

### Layer 6 — 时刻注入

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 用户逐站指定 `timetableAnchors[]` | 完全手动 |
| 2 | `ServicePattern.defaultTimetable` 匹配 | 管理后台内置时刻表 |
| 3 | 速度推断 | 60km/h 默认速度 + 停站 dwell 30s |
| 4 | 无时刻信息 | 仅 `RunOrder`，无 `TimelinePoint`，事件仅有序号无时间 |

### Layer 7 — 事件生成

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | `ServicePattern.stationSequence[].stopType` | mandatory_stop → platform_stop；pass_through → platform_pass |
| 2 | `RunSpec.eventPolicy` 覆盖 | 用户强制某站从 pass 改为 stop |
| 3 | 自动推断 | 换乘边界自动推 `line_transfer`；系统变更边界自动推 `system_change` |
| 4 | 附加事件（绝景/用户） | 空间锚点投影到 orderIndex |

### Layer 8 — 渲染输出

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | `ServicePattern.displayColor/displayName` | 每条线的渲染样式 |
| 2 | InfraEdge.geometry 坐标拼接 | 物理几何 |
| 3 | `DoubleTrackRelation` 动态偏移 | 需要偏移时叠加 |
| 4 | landmark 标签 | `stationSequence` 中 `landmark=true` 的站名收集 |

## 3. 换乘自动发现与事件统一

### 3.1 换乘点自动发现

管理员配置好所有 ServicePattern 后，**不需要手动创建换乘关系**。系统自动检测：

```
ServicePattern A (东海道线):
  stationSequence: [东京, 新桥, 品川, 川崎, 横浜, 大船, 小田原, 热海]

ServicePattern B (湘南新宿线):
  stationSequence: [宇都宫, 大宫, 池袋, 新宿, 涩谷, 武藏小杉, 横浜, 镰仓, 小田原]

→ 自动检测交集: { 横浜, 小田原 }
→ 生成 TransferPoint:
   { nodeRef: "N_YOKOHAMA",  patterns: [A, B] }
   { nodeRef: "N_ODAWARA",   patterns: [A, B] }
```

检测算法（`graph-builder.ts` 构建 ServicePattern 后执行）：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 同一 InfraNode 出现在 2+ ServicePattern 的 `stationSequence` 中 | 自动标记为 TransferPoint |
| 2 | 管理员显式添加的 `transfer` relation | 覆盖/补充自动检测（如步行换乘、不同站换乘） |
| 3 | 同一 ServicePattern 内跨线（`line_transfer` vs `through_service`） | `inferTransferMode` 按线路归属/系统规则判定 |

管理员只需确保：
- 每个 ServicePattern 的 `stationSequence` 正确
- 共线段使用相同的 InfraNode ID 引用同一车站

其余换乘网络自动从交集推导。

### 3.2 事件源统一

所有事件最终合并到一条时间线，但**来源不同，暴露程度不同**：

```ts
type EventSource = 
  | "system"      // 系统生成：platform_stop, platform_pass, switch_pass, special_section_pass
  | "transfer"    // 换乘自动推断：line_transfer, through_service, system_change
  | "timetable"   // 时刻表注入：为 system/transfer 事件附加时间戳
  | "user"        // 用户创建：user_defined
  | "inferred"    // 补全推断：缺失数据自动补全产生的事件标记
```

| 事件源 | 谁生成 | 管理员可见/可编辑 | 终端用户可见/可编辑 |
|---|---|---|---|
| `system` | events.ts | ✅ 可编辑（配置 stopType / eventPolicy） | ✅ 只读 |
| `transfer` | graph-builder 自动检测 + events.ts 推断 | ✅ 可编辑（修正 transferMode / 添加除外规则） | ✅ 只读 |
| `timetable` | timeline.ts 注入 | ✅ 可编辑（修改时刻表数据） | ✅ 只读（但可选择日期/班次） |
| `user` | 终端用户创建 | ✅ 只读（审核用途） | ✅ 可创建/编辑/删除 |
| `inferred` | enrichment.ts | ✅ 可审核/确认/拒绝 | ❌ 不可见（内部诊断用） |

### 3.3 具体场景：东海道线 → 湘南新宿线

管理后台配置完毕，用户规划行程。

```
请求: TripPlanRequest {
  systemId: "jr-east-2026",
  startStationRef: "N_TOKYO",       // 东京
  endStationRef: "N_KAMAKURA",      // 镰仓
}
```

系统内部决策链：

```
Layer 1 (系统匹配)：
  起终点均在 "jr-east-2026" 内 ✅

Layer 2 (线路匹配)：
  东京 ∈ 东海道线 stationSequence ✅
  镰仓 ∉ 东海道线 stationSequence ❌
  镰仓 ∈ 湘南新宿线 stationSequence ✅
  东京 ∉ 湘南新宿线 stationSequence ❌
  → 单线无法覆盖，进入跨线搜索
  → 自动检测 TransferPoint: { 横浜: [东海道线, 湘南新宿线], 小田原: [东海道线, 湘南新宿线] }
  → 候选路径:
    Path1: 东京→(东海道线)→横浜→(换乘)→横浜→(湘南新宿线)→镰仓
    Path2: 东京→(东海道线)→小田原→(换乘)→小田原→(湘南新宿线)→镰仓

Layer 3 (方向决策)：
  东海道线 东京→横浜: 下行 ✅
  湘南新宿线 横浜→镰仓: 南行 ✅

Layer 4 (评分)：
  Path1: 东京→横浜(28km) + 横浜→镰仓(22km) = 50km ✅ 胜出
  Path2: 东京→小田原(83km) + 小田原→镰仓(27km) = 110km
```

### 3.4 事件合并规则

同一 orderIndex 允许多事件共存，合并后的展示顺序：

```
同站事件展示优先级:
  transfer (换乘信息) → stop (到/发) → pass (通过) → scenic (绝景) → note (用户)
```

时间戳相同时按上述优先级排列。管理员和终端用户看到的事件列表相同（均为 `TripEvent[]`），但终端用户只能对 `source="user"` 的事件做增删改。

## 4. 对外接口草稿

### 3.1 总体使用流

```
管理后台                         部署                    终端用户
──────────                    ────────                  ──────────
创建 ServicePattern[]           │                        │
绑定站台/方向/时刻表            │                        │
验证 → 固化 →           DeployedSystem               │
                             │                        │
                          PathPreset[] (自动生成)       │
                             │                        │
                             └──── 分发 ────→     选择 Preset
                                                  或输入起终点自动规划
                                                      │
                                                  TripPlan
                                                      │
                                                  TripResult
                                                    (固化, 不再选线)
```

### 3.2 核心抽象

```ts
// ========== 管理后台产物 ==========

/** 一次部署：包含所有已绑定的运行系统、线路、时刻表 */
interface DeployedSystem {
  systemId: string;
  version: string;                    // 部署版本号
  createdAt: string;
  servicePatterns: ServicePattern[];  // 所有运行线路
  stations: StationMeta[];            // 所有站的元数据（名称、坐标、landmark）
  relations: SystemRelation[];        // 站台绑定、换乘关系、复线关系
  defaultTimetables: TimetableSet[];  // 内置时刻表集
  generatedPresets: PathPreset[];     // 预计算的路径模板
}

/** 管理后台编辑态（部署前） */
interface EditableDeployment {
  systemId: string;
  draftVersion: string;
  graph: RailGraph;                    // 完整的可编辑图
  pendingPatches: PatchSet[];          // 待审核的修改
  diagnostics: Diagnostic[];           // 自动补全/冲突诊断
  snapshot: EditableRailGraphSnapshot; // 可回放快照
}

// ========== 部署后自动生成 ==========

/** 固化后的路径模板——用户看到的最小单位 */
interface PathPreset {
  presetId: string;
  label: string;                       // "山手线 内回り 新宿→上野"
  shortLabel: string;                  // "新宿→上野"
  serviceLabel: string;                // "JR山手線 内回り"
  displayColor: string;
  startStation: StationRef;
  endStation: StationRef;
  viaStations: StationRef[];           // 途中经停站
  landmarkLabels: string[];            // "新宿・渋谷 方面"
  directionLabel: string;              // "内回り"
  estimatedTimeMinutes: number;
  distanceKm: number;
  // 内部引用（用户不可见）
  runSpec: RunSpec;                    // 固化后 RunSpec 不再暴露给用户
}

// ========== 用户侧接口 ==========

/** 用户发起一次规划请求 */
interface TripPlanRequest {
  // 方式一：选 Preset
  presetId?: string;
  // 方式二：自由规划
  systemId: string;                    // 在哪个部署系统内
  startStationRef: StationRef;
  endStationRef: StationRef;
  viaRefs?: StationRef[];              // 可选"经过"
  directionPreference?: string;        // 可选方向偏好
  date?: string;                       // 可选日期（影响时刻表选择）
}

/** 规划结果——固化输出，用户不再调内部参数 */
interface TripResult {
  tripId: string;
  presetId?: string;                   // 如果来自 preset
  planUsed: "preset" | "auto";
  segments: TripResultSegment[];       // 分段（跨线时多段）
  totalDistanceKm: number;
  totalTimeMinutes: number;
  // 以下为内部固化数据——用户不可见、不可改
  internalRunPaths: RunPath[];         // 每段的内部路径
}

interface TripResultSegment {
  lineLabel: string;                   // "JR山手線 内回り"
  displayColor: string;                // "#80C241"
  fromStation: StationMeta;
  toStation: StationMeta;
  viaStations: StationStop[];          // 按顺序的全部途经站，含停/通过区分
  landmarkLabel: string;               // "品川・渋谷 方面"
  distanceKm: number;
  timeMinutes: number;
  geometry: GeoJSON.LineString;        // [lat, lng][] 可直接渲染
  events: TripEvent[];                 // 按时间排列的全部事件
}

/** 途经站——携带停/通过区分和时间，UI 可直接渲染 */
interface StationStop {
  station: StationMeta;
  stopType: "stop" | "pass";
  arrivalTime?: string;               // ISO 时间或 HH:MM
  departureTime?: string;
}

/** 站元数据——UI 所需的最小字段 */
interface StationMeta {
  stationRef: string;
  name: string;                        // "東京"
  nameJa?: string;                     // "東京"
  coordinates: [number, number];       // [lat, lng]
  landmark?: boolean;
}

/** 用户可见事件——按类型携带不同字段 */
type TripEvent =
  | TripStopEvent
  | TripPassEvent
  | TripTransferEvent
  | TripScenicEvent
  | TripNoteEvent;

interface TripStopEvent {
  type: "stop";
  source: "system" | "timetable";
  stationRef: StationRef;
  label: string;                       // "停靠 横浜"
  arrivalTime?: string;
  departureTime?: string;
  durationMinutes?: number;            // 停站时长
}

interface TripPassEvent {
  type: "pass";
  source: "system" | "timetable";
  stationRef: StationRef;
  label: string;                       // "通過 川崎"
  passTime?: string;
}

interface TripTransferEvent {
  type: "transfer";
  source: "transfer";
  label: string;                       // "乗換: JR東海道線 → JR湘南新宿ライン"
  timestamp?: string;
  fromLine?: string;
  toLine?: string;
  transferMode?: "alight" | "through"; // 下车换乘 / 同车直通
  walkMinutes?: number;                // 步行换乘时间（如不同站）
}

interface TripScenicEvent {
  type: "scenic";
  source: "system" | "user";
  label: string;                       // "車窓: 富士山"
  timestamp?: string;
  title?: string;
  description?: string;
  imageUrls?: string[];
  viewSide?: "left" | "right" | "front" | "back";
}

interface TripNoteEvent {
  type: "note";
  source: "user";
  label: string;                       // "在这里买便当"
  timestamp?: string;
  text?: string;
  imageUrls?: string[];                // 用户上传的图片
}

// ========== 部署/同步接口（方向性，不设计细节） ==========

interface DeploymentAPI {
  /** 管理后台：导出固化部署包 */
  exportDeployment(editable: EditableDeployment): DeployedSystem;

  /** 管理后台：验证部署包的自洽性 */
  validateDeployment(system: DeployedSystem): ValidationResult;

  /** 管理后台：从编辑态生成所有 PathPreset */
  generatePresets(system: DeployedSystem, options?: {
    maxPresetsPerLine?: number;    // 每条线最多生成多少 preset（如只生成相邻 5 站内的组合）
    minDistanceKm?: number;        // 最短路径阈值（过滤同站/极短路径）
  }): PathPreset[];

  /** 用户端：给定请求 → 规划结果 */
  planTrip(request: TripPlanRequest, system: DeployedSystem): TripResult;

  /** 用户端：列出某个部署系统中可用的全部 Preset */
  listPresets(systemId: string, filter?: {
    lineRef?: string;
    startStationRef?: string;
  }): PathPreset[];
}
```

## 4. 接口边界约束

### 4.1 用户端可见 vs 不可见

| 可见 | 不可见 |
|---|---|
| `TripResult` 全部字段 | `RunPath`, `RunSpec` 内部结构 |
| `PathPreset.label` / `.landmarkLabels` / `.estimatedTimeMinutes` | `PathPreset.runSpec` (序列化但不暴露) |
| `TripResultSegment.geometry` (可直接画) | `RenderGeometryPlan` 内部结构 |
| `TripEvent.type` / `.label` / `.timestamp` | `RunEvent` 内部枚举和 payload |
| `StationMeta.name` / `.coordinates` | `InfraNode` 完整属性 |

### 4.2 固化保证

- `DeployedSystem` 导出后，内部不再有 `any`、不再有未解析的诊断（`error` 和 `fatal` 级必须在部署前清零）
- `PathPreset.runSpec` 已完整解析，用户端不会触发 `path-resolver.ts` 的自动决策（除非用户选择"自由规划"模式）
- `TripResult` 是一次性快照，不持有对 `RailGraph` 的引用；geometry 已从 InfraEdge 坐标拼接完整
- 用户端的"auto"规划也是在 `DeployedSystem` 内搜索——不需要访问原始 ORM/GeoJSON 输入

## 6. UI 可行性逐模式确认

### 6.1 地图渲染

```
输入: TripResultSegment.geometry + .displayColor
      viaStations[].station.coordinates + .stopType

绘制:
  polyline: geometry → Leaflet L.polyline({ color: displayColor })
  stop 图标: viaStations.filter(s => s.stopType === "stop") → L.marker 实心圆
  pass 图标: viaStations.filter(s => s.stopType === "pass") → L.marker 空心圆
```

✅ `geometry` 是 `[lat, lng][]`，Leaflet/MapLibre 直接消费。`displayColor` 是 hex 字符串，直接映射样式。`StationStop` 携带坐标和 stop/pass 区分，不需要二次 join。

### 6.2 时间线视图

```
输入: TripResultSegment.events (按时间排序)
      viaStations[].arrivalTime / .departureTime

渲染: 每条 TripEvent 一个 timeline entry

stop  entry: 实心圆点 + label + arrivalTime→departureTime (durationMinutes)
pass  entry: 空心圆点 + label + passTime
transfer entry: 换乘图标 + label + timestamp + fromLine→toLine badge
scenic entry: 景观图标 + label + title/description 可展开 + viewSide 图标
note  entry: 用户图标 + label + text + imageUrls 缩略图
```

✅ 五种事件类型各自携带 UI 所需的结构化字段。`source` 字段可用于控制编辑权限（user 可删，其他只读）。时间信息完整（stop 有到/发/时长，pass 有通过时刻，transfer 有换乘时刻）。

### 6.3 行程卡片/列表

```
输入: TripResult.tripId, .totalDistanceKm, .totalTimeMinutes
      segments[0].lineLabel + .displayColor (主线路)
      segments[].fromStation.name → toStation.name
      Preset 或第一个 segment 的 landmarkLabel

卡片:
  ┌──────────────────────────────────────────┐
  │ [绿] JR山手線 内回り                       │  ← displayColor 色条 + lineLabel
  │ 東京 → 鎌倉                               │  ← segments[0].from → segments[-1].to
  │ 50km · 40分                               │  ← totalDistanceKm / totalTimeMinutes
  │ 经由 品川・大船 方面                       │  ← landmarkLabel
  └──────────────────────────────────────────┘
```

✅ 所有卡片字段都在 `TripResult` 和 `PathPreset` 的顶层，无需深入 segments。

### 6.4 换乘行程卡片

多段行程（跨线时 > 1 segment）的卡片额外展示换乘信息：

```
  ┌──────────────────────────────────────────┐
  │ [橙] JR東海道線 下行                       │
  │ 東京 → 横浜 · 28km · 18分                  │
  │    ↓ 横浜 乗換 7分                         │  ← 从第二个 segment 的 transfer event 提取
  │ [赤] JR湘南新宿ライン 南行                  │
  │ 横浜 → 鎌倉 · 22km · 15分                  │
  │ 合計 50km · 40分                           │
  └──────────────────────────────────────────┘
```

✅ 换乘信息来自 `TripTransferEvent` 的 `fromLine`/`toLine`/`timestamp`/`walkMinutes`，以及两个 segment 的时间/距离。

### 6.5 不可行的情况

| 场景 | 可行性 | 说明 |
|---|---|---|
| UI 需要渲染"当前列车实时位置" | ❌ 不在此阶段 | 需要实时 GPS/信号数据，不属于固化路径系统 |
| UI 需要交互式"拖拽站点调整路径" | ❌ 不在此阶段 | 需要 pathOverride 编辑接口，可在后续实现 |
| UI 需要时刻表日历视图 | ✅ 可行 | `PathPreset` + `DeployedSystem.defaultTimetables` 提供数据，UI 自行排布 |
| UI 需要导出 GPX/KML | ✅ 可行 | `TripResultSegment.geometry` 已是 GeoJSON，可无损转换 |
| UI 需要多语言 (i18n) | ✅ 可行 | `label` 字段由系统生成时已本地化；`StationMeta.name`/`nameJa` 双字段支持 |
| UI 需要离线缓存 | ✅ 可行 | `DeployedSystem` + `PathPreset[]` 整体可 JSON 序列化存入 IndexedDB |

## 7. 当前阶段不做

- 不设计具体的 HTTP/gRPC/文件导入导出格式
- 不设计 Preset 生成策略的完整参数（maxPresetsPerLine 等，实现时迭代）
- 不设计用户端 UI 交互细节
- 不设计版本升级/回滚/差异对比

当前保证：`DeployedSystem` 和 `TripResult` 两个抽象已足够隔离管理后台和用户端的职责边界。内部组件（graph-builder / path-resolver / render-geometry / events）的任意变更，只要不改变这两个抽象的 schema，对用户端透明。
