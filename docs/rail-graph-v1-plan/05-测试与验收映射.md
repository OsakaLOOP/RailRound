# 测试与验收映射

## 1. 测试目标
本文件定义实现阶段的测试范围与验收口径，确保新对象系统满足：
- 结构完备
- 行为可解释
- 缺失可补全
- 兼容可落地

## 2. 模块到测试映射

### 2.1 `ids.ts`
- 用例：
  - 同输入生成同 ID（幂等）
  - 缺失源 ID 时 fallback 稳定
  - 非法 ID 格式校验
- 验收：无随机漂移 ID。

### 2.2 `normalizers.ts` + `contracts.ts`
- 用例：
  - 多源混合输入标准化
  - 缺字段默认补全
  - 非法字段记录诊断
  - GeoJSON `kind + geometry` 组合校验
  - `Polygon/MultiPolygon` 站台面进入 `areas[]`
  - `MultiLineString` 站线拆成可寻址 edge slice
- 验收：输出结构完整，诊断可追溯。

### 2.2.1 `geojson-contracts.ts`
- 用例：
  - `platform_area` 只接受 `Polygon/MultiPolygon`
  - `track_geometry` 接受 `LineString/MultiLineString`
  - `switch_point` 只接受 `Point`
  - `special_section` 区分 `category` 与 `directionSeparation`
  - legacy GeoJSON 自定义字段可检测并映射到新 kind
- 验收：强类型契约能覆盖 `06` 新增对象，不把弱字段泄露到核心流程。

### 2.3 `graph-builder.ts`
- 用例：
  - 站台/股道/道岔/桥隧/复线实体建图
  - 层间关联正确建立
  - 断裂图检测
  - 站台面通过 relation 绑定站线
  - 道岔点动态吸附到相邻线并写入 adjacency
- 验收：图索引一致，连通性检查可用；点吸附缺失或不确定时有诊断。

### 2.4 `path-resolver.ts`
- 用例：
  - 自动路径选择
  - 手动 override 覆盖
  - 上下行/复线候选评分解释
  - 存车线默认不进入普通候选
  - 用户事件不参与候选评分
- 验收：同输入路径稳定，可输出评分理由；额外事件层不改变寻路结果。

### 2.4.1 `render-geometry.ts`
- 用例：
  - 复线仅有真实物理 edge
  - 复线仅有动态偏移计划
  - 复线同时具备真实物理 edge 与动态偏移计划
  - 动态偏移在并线/分线/道岔/桥隧出入口生成平滑连接计划
  - `MultiLineString` edge slice 按运行路径拼接
- 验收：每组复线至少具备 `physical_edges` 或 `dynamic_offset` 之一；渲染计划不反写拓扑真源。

### 2.5 `timeline.ts`
- 用例：
  - 仅顺序生成时间点
  - 部分锚点插值
  - 冲突锚点修正
- 验收：时间单调，插值点标记 `isSynthesized`。

### 2.6 `events.ts`
- 用例：
  - 停靠/跨越站台事件
  - 道岔事件
  - 特殊区间事件
  - 系统切换事件
  - 跨线与同车直通边界事件
  - 编组/解挂作业事件
  - 车窗绝景事件
  - 用户创建事件
- 验收：事件有序、可追溯、可选带时间戳。

### 2.6.1 `event-anchors.ts`
- 用例：
  - 地图固定点绝景绑定到最近运行 order/time
  - 地图绝对方向转换为运行车窗侧与相对方向
  - 用户事件绑定到 order/time/entity/geometry anchor
  - 用户事件不影响 `RunPath`
- 验收：事件锚点解析可复现，方向转换结果可解释。

### 2.7 `enrichment.ts` + `diagnostics.ts`
- 用例：
  - 缺失字段自动补全
  - 不同级别诊断聚合
  - fatal 阻断流程
  - 缺失站台-站线关系推断
  - 缺失复线物理几何时生成动态偏移 patch
- 验收：补全不静默，fatal 行为可预测。

### 2.8 `patch.ts` + `editing.ts`
- 用例：
  - add/update/remove/link patch
  - replace geometry patch
  - add/update event anchor patch
  - update event policy patch
  - preview 与 apply 一致
  - EditableSnapshot 导出后可回放
- 验收：patch 不破坏稳定 ID 与图一致性；编辑输出不污染原始输入。

### 2.9 `adapters/*`
- 用例：
  - legacy networkMeta 映射完整
  - ORM 输入映射
  - OpenRailwayMap 输入映射
- 验收：兼容层语义不丢失。

## 3. 场景级验收

### 3.1 复合线路场景
- 包含：复线、上下行分离、桥隧分离、存车线、道岔。
- 验收：路径可唯一确定，事件链正确；复线真实几何/动态偏移至少其一存在，动态偏移有平滑连接计划。

### 3.2 跨线运行场景
- 包含：跨线后系统/车种/服务别变更。
- 验收：边界事件完整，transferMode/requiresTransfer 可解释。

### 3.3 缺失与冲突场景
- 包含：字段缺失、方向冲突、局部断裂。
- 验收：流程尽可能继续，诊断准确分级。

### 3.4 车窗绝景场景
- 包含：固定地图点绝景、地图方向绝景、运行方向变化。
- 验收：绝景事件能绑定顺序/时间，地图方向可转换为车窗侧与相对方向。

### 3.5 用户事件场景
- 包含：用户自定义事件、图片/说明 payload、空间锚点、时间锚点。
- 验收：用户事件能保存、排序、导出、回放，且不改变寻路。

### 3.6 编辑输出场景
- 包含：自动补全 patch、人工 link patch、事件 anchor patch、几何替换 patch。
- 验收：preview/apply/export 一致，snapshot 可人工审阅。

## 4. 回归兼容验收
- 对照现有 `networkDisplay` 行为，验证：
  - `subSegments/events/systems`
  - `common/byDirection`
  - 自动 transfer 补全
- 验收：兼容输入在新系统下不退化。

## 5. 最终通过标准
以下全部满足视为通过：
1. 核心主链可闭环跑通（离线）。
2. 所有关键模块有对应测试与明确断言。
3. 关键场景输出结果可人工审阅且可复现。
4. 无 `fatal` 时可稳定产出 `RunPath + RenderGeometryPlan + Timeline + EventStream + EditableSnapshot`。
5. GeoJSON/JSON 契约覆盖 `06` 的新增隐含条件。
