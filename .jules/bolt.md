## 2026-03-31 - [Optimized Iteration over large collections]
**Learning:** Found an opportunity to replace chained array methods like flatMap, map, reduce, and Object.values/keys with single-pass manual 'for' and 'for...in' loops when processing arrays and objects to avoid allocating large temporary data structures. Used ES6 Maps/Sets where efficient counting/deduplication was needed.
**Action:** Apply this pattern to other performance sensitive areas where objects and arrays map over large datasets, and ensure that iteration checks 'Object.prototype.hasOwnProperty.call()' when utilizing 'for...in'. Note: This project lacks a package.json at the root so standard npm/pnpm lint tools might not be readily available.

## 2026-04-01 - [Map and Route Dragging Performance]
**Learning:** React component re-renders (specifically `clearLayers` in Leaflet maps) can be extremely expensive. `MapContainer.tsx` was passing `railwayData` into `useEffect` that called `renderBaseMap(geoData)` even though it only depended on `geoData`. Any background updates to `railwayData` (like distance workers) caused massive Leaflet DOM rebuilds. Also, routing snaps (`findNearestPointOnLine` in `railwayRouting.ts`) were checking point-to-segment projection math for every station in Japan on every mouse move tick.
**Action:** When working with Leaflet or any manual DOM manipulation inside React `useEffect`, strictly minimize dependency arrays to avoid triggering expensive map rebuilds. For geospatial algorithms evaluating large datasets (like all railway lines in a country), always implement a fast bounding-box rejection pre-check before doing trig/Euclidean math.
