# 设计约束与不变量

## 1. 总体约束
- 仅设计与文档阶段，不接入现有应用执行链。
- 新系统必须严格 TypeScript，禁止 `any` 作为对外接口类型。
- 所有模块边界必须可序列化，便于调试快照与离线重放。
- GeoJSON 仅作为原始几何与外部标签输入层；标准化 JSON 是图结构、运行计划、事件流与编辑输出的唯一契约。

## 1.1 GeoJSON 输入约束
- 每个 GeoJSON feature 必须通过 `properties.railGraph.kind` 表达强语义。
- 允许的核心 geometry 映射：
  - 站台：`Polygon/MultiPolygon -> InfraArea(kind=platform)`
  - 站线/股道/存车线/桥隧线：`LineString/MultiLineString -> InfraEdge`
  - 道岔：`Point -> InfraNode(kind=switch)`
  - 特殊区间：`LineString/MultiLineString/Polygon -> SpecialSection`
  - 事件锚点：`Point/LineString -> EventAnchor`
- 外部标签可保留，但核心逻辑不得直接依赖未标准化的弱类型字段。

## 2. 主键与实体约束

### 2.1 稳定 ID 约束
- 优先使用外部源实体 ID（ORM/OpenRailwayMap 原始 ID）。
- 无外部 ID 时，使用 deterministic 规则生成（同源同字段必然同 ID）。
- ID 格式约定：`{source}:{entityType}:{stablePart}`。

### 2.2 实体唯一性不变量
- 同一 `entityType` 下，ID 全局唯一。
- 同实体多来源合并时，保留 `sourceRefs[]` 与 `provenance`。
- 任何补全行为不得改变既有稳定 ID。

## 3. 图结构约束（统一多层图）

### 3.1 多层模型
- 基础设施层：站台、股道、道岔、桥隧区段、存车线等物理实体。
- 服务层：上下行、复线路径、运行系统、服务别名等运营语义。
- 事件附加层：固定事件、车窗绝景、用户事件等时空语义锚点；用户事件不参与寻路。
- 运行时层：一次具体 run 的路径、渲染几何计划、事件、时间点、诊断。

### 3.2 连通性不变量
- 每条可运行路径必须映射到一条可连通 edge 序列。
- 方向约束必须落在边级（而非仅线级字符串标签）。
- 环线必须支持两方向候选并可被显式指定覆盖。
- 道岔等点对象到线对象的吸附属于底层动态计算，结果必须进入 adjacency 或运行时连接诊断。

### 3.3 面/线/点/区间不变量
- 站台面不直接替代站线；站台与站线必须通过 relation 绑定。
- `MultiLineString` 可作为输入，但标准化后必须拆成可寻址 edge 或 edge slice。
- 桥隧上下行分离必须拆成物理类别 `category` 与方向分离 `directionSeparation` 两个语义。
- 存车线默认不进入普通运行路径候选，只能由 manual override、作业事件或专用策略引用。

### 3.4 复线不变量
- 复线关系必须同时兼容真实物理 edge 与动态偏移计划。
- 每组复线至少具备 `physical_edges` 或 `dynamic_offset` 之一。
- 当二者同时存在时，真实物理 edge 优先作为拓扑依据；动态偏移用于显示修正、缺口补全或调试对照。
- 动态偏移必须带有平滑连接策略，避免在并线、分线、道岔、桥隧出入口产生突变。

## 4. 路径与顺序约束

### 4.1 顺序优先模型
- 先确定 `RunOrder`（离散有序点序列），再派生时间与事件。
- 若显式路径存在，优先采用显式路径；自动决策仅在缺失时触发。

### 4.2 自动决策不变量
- 自动决策必须可解释（输出评分与选择理由）。
- 相同输入多次计算结果一致（幂等）。
- 自动决策可被人工 override，且 override 优先级最高。

## 5. 时间轴约束

### 5.1 时间模型
- 必须支持两类时间输入：
  - 仅顺序（无绝对时刻）
  - 部分/完整时刻表锚点
- 中间时刻插值由 utils 统一实现。

### 5.2 时间不变量
- 时间点单调不减（允许同时刻事件）。
- 缺失时刻必须标注 `isSynthesized=true`。
- 冲突时刻不直接中断，记录冲突诊断并执行可预测修正。

## 6. 事件层约束

### 6.1 事件覆盖范围
至少覆盖：
- 停靠站台
- 跨越站台（不停）
- 经过道岔
- 经过特殊区间（桥/隧/上下行分离区段）
- 运行系统/车种/服务别切换
- 跨线/同车直通/需下车换乘
- 编组作业、解挂作业
- 车窗绝景
- 用户创建事件

### 6.2 事件不变量
- 事件必须绑定顺序索引。
- 事件可选绑定时间戳。
- 每个边界事件必须可追溯到路径片段或规则来源。
- 车窗绝景必须支持两种锚定：地图固定点、按运行方向的车窗视角。
- 车窗绝景若输入地图绝对方向，必须能转换为运行方向下的车窗侧与相对方向。
- 用户事件属于额外时空语义层，只与车辆运行相对绑定，不参与路径候选评分或寻路。

## 7. 缺失数据与补全约束

### 7.1 补全策略
- 优先“合理可运行”而非“严格报错中断”。
- 缺字段采用默认值与推断值，但必须附带诊断。
- 关键缺失（如路径断裂）可标记致命并停止该 run 生成。

### 7.2 诊断分级
- `info`：正常补全提示
- `warn`：有风险但可继续
- `error`：当前对象不可用但可局部降级
- `fatal`：主流程无法继续

### 7.3 编辑输出不变量
- 自动补全、人工修正、事件锚点新增必须可表达为 `PatchSet`。
- patch 必须支持 preview/apply/export，不直接污染原始 GeoJSON/ORM 输入。
- debug snapshot 必须包含图、运行计划、事件流、待应用 patch 与诊断。

## 8. 兼容约束
- 必须兼容现有 `networkMeta` 三种输入形态。
- 必须兼容现有 `TripSegment` 输入语义。
- 必须保留 `loopVia` 的用户显式意图。

## 9. 工程约束
- 新模块不得依赖 UI 状态容器（如 Zustand store）作为核心输入。
- 所有核心函数采用纯函数优先，副作用集中在 adapter/debug 边界。
- 每阶段产物都可 JSON 快照导出，便于人工审阅与回归对比。
