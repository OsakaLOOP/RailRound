### 2.3 ⚠️ 发现的不一致

#### C1: `RunPathResult` 类型定义缺失

- **位置**: `03-TS文件级蓝图.md` §2.7 返回 `RunPathResult`
- **问题**: 该类型在 03#2.1 `types.ts` 导出清单中未列出，04#2.5 只定义了 `RunPath` 而非 `RunPathResult`
- **严重度**: 低（实现时容易补全）
- **建议**: 03#2.1 types.ts 补充 `RunPathResult = { path: RunPath; diagnostics: Diagnostic[] }`

#### C2: `BuildRailGraphPipelineResult` 与 `BuildGraphResult` 的关系

- **位置**: `03-TS文件级蓝图.md` §3.1 返回 `BuildRailGraphPipelineResult`，但 §2.6 `buildRailGraph` 返回 `BuildGraphResult`
- **问题**: 两个 result 类型名不同但语义重叠（均含 graph + diagnostics + stats）
- **严重度**: 低（命名标准化即可）
- **建议**: 统一为 `BuildGraphResult`，pipeline 入口为其子集或别名

#### C3: `EventStream` 定义位置模糊

- **位置**: 03#2.10 `events.ts` 返回 `EventResult`，04#2.8 定义 `EventStream`；03#2.1 types.ts 只列出 `RunEvent, TimelinePoint, EventAnchor`，无 `EventResult` 或 `EventStream`
- **问题**: 03 和 04 对事件输出的类型名称不一致
- **严重度**: 低
- **建议**: 03#2.10 返回类型改为 `EventStream` 或明确 `EventResult = { events: RunEvent[]; diagnostics: Diagnostic[] }`

### 2.4 ✅ 已验证的一致关系

- **03→04 主链闭环**: `SourceInput → NormalizedEntityBatch → RailGraph → RunSpec → RunPath → RenderGeometryPlan → RunOrder → Timeline → EventAnchorResolution → EventStream → EditableSnapshot → PatchSet → Diagnostics` 在各文档中均一致出现

### 4.2 场景二：环线自动方向决策 + 部分时刻表

**描述**: ORM 环形线路数据，用户不指定方向，系统自动选；部分站有 timetable 锚点，中间站需插值。

**数据流追踪**:

```
[输入] SourceBatchInput (环形线路，共 5 站: S0→S1→S2→S3→S4→S0)
  sources: [{ sourceType: "orm_records", ... }]
    ↓
[标准化] NormalizedEntityBatch
  nodes: [S0, S1, S2, S3, S4]  (每个既是 station node 也是环线上的一点)
  edges: [e0(S0→S1, up), e1(S1→S2, up), ..., e0'(S0→S4, down), ...]
  servicePatterns: [{ type: "loop", edgeRefs: [...all edges...] }]
    ↓
[建图] RailGraph
  adjacency: { e0: S0→S1, e1: S1→S2, e2: S2→S3, e3: S3→S4, e4: S4→S0 }
    ↓
[路径] RunSpec { startRef: "S0", endRef: "S3", directionHint: "unknown" }
    ↓ path-resolver.ts
    ① computeLoopVia-like 逻辑: 计算 S0→S3 的 up 路径长度 vs down 路径长度
       up: e0+e1+e2 (S0→S1→S2→S3) = 30km
       down: e4+e3 (S0→S4→S3) = 18km
    ② 方向一致性检查: 无前后段（单段环线运行）→ 回退到方案 ②
    ③ 选择 down（较短）
[路径结果] RunPath
  edgeSequence: [e4, e3]
  chosenDirection: "down"
  resolvedBy: "auto"
  candidateScores: [{ pathId: "down", score: 0.85, reason: "down方向路径较短(18km vs 30km)" },
                     { pathId: "up", score: 0.55, reason: "up方向路径较长(30km)" }]
    ↓
[渲染] 直接拼接 e4+e3 坐标 ✅
    ↓ timeline.ts
[顺序] RunOrder: [S0(0), S4(1), S3(2)]
[锚点] timetableAnchors: [{ stationRef: "S0", timestamp: "09:00" }, { stationRef: "S3", timestamp: "09:25" }]
    ↓ synthesizeTimeline(S0=09:00, S3=09:25, 中间 S4 无锚点)
[时间] TimelinePoint[]
  [{ orderIndex: 0, timestamp: "09:00", isSynthesized: false },
   { orderIndex: 1, timestamp: "09:15", isSynthesized: true, inference: "speed_distance" },
     // S0→S4 = 40% of total S0→S3, 40% × 25min = 10min → 09:10... but also need dwell at S0
     // 实际: 锚点间隔 25min, 距离 S0→S4=8km, S4→S3=10km
     // S0→S4: 8/18 × 25min ≈ 11.1min, dwell S0=30s → 09:11:40
     // S4→S3: 10/18 × 25min ≈ 13.9min → 09:25 (匹配锚点)
   { orderIndex: 2, timestamp: "09:25", isSynthesized: false }]
    ↓ events.ts
[事件] EventStream
  events: [{ eventType: "platform_stop", orderIndex: 0, ... },
           { eventType: "platform_pass", orderIndex: 1, ... },  // ⚠️ S4 是跨越还是停靠？需从 RunSpec.eventPolicy 判断
           { eventType: "platform_stop", orderIndex: 2, ... }]
```
