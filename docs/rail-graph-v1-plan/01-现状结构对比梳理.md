# 现状结构对比梳理

## 1. 当前真实结构（代码已存在）

### 1.1 数据入口与承载
- 全局状态：`src/store/index.ts`
  - `railwayData: RailwayMap`
  - `geoData: CustomFeatureCollection`
  - `segmentGeometries: Map<string, any>`
  - `tripSegmentsGeometry: any[]`
- 线路元数据：`RailwayLineMeta.networkMeta?: any`（当前为弱类型）

### 1.2 GeoJSON 解析与兼容层
- 解析入口：`src/core/parser.ts#parseGeoJsonBatch`
- 现有兼容能力：
  - 支持 `networkMeta` 的三种形态：
    - 旧平铺：`{ subSegments, events, systems }`
    - 新结构：`{ common, byDirection }`
    - 方向注入：当 feature 带 `direction=up/down` 时归并至 `byDirection`
  - merge 规则：
    - 对象字段浅合并
    - `subSegments/events/systems` 数组采用后值覆盖
- 局限：
  - `networkMeta` 类型为 `any`
  - 无 schema 级校验与诊断分级
  - 归并缺少版本化与来源追踪
  - GeoJSON feature 尚未区分 `platform_area/track_geometry/switch_point/special_section/event_anchor` 等强语义 kind
  - 面、线、点、区间与事件锚点尚未进入统一标准化 JSON 层级

### 1.3 几何切片与方向处理
- worker：`src/workers/geo.worker.js`
- 现有能力：
  - `SYNC_DATA` 同步 `railwayData/geoData`
  - `GET_ALL_GEOMETRIES` 批量生成 segment geometry
  - 对环线/方向：
    - `loopVia` 或自动判定 `up/down`
    - 优先找有 `properties.direction` 的线要素
    - 回退到无方向要素
  - MultiLineString：`stitchRoutes` + 切片
  - 回退链：
    - feature 切片失败 -> 站点序列折线 -> 两点直线
- 局限：
  - 文件为 JS，类型系统缺位
  - 几何与运行语义耦合（direction/path/event 逻辑混在同层）
  - 回退行为无统一诊断模型
  - 复线缺少“真实物理 edge + 动态偏移计划”并存模型，动态偏移也缺少平滑连接描述
  - 道岔等点对象未作为底层图构建吸附逻辑的一等输入

### 1.4 运行显示语义（network_base 兼容层）
- 核心：`src/utils/networkDisplay.ts`
- 当前已支持：
  - `subSegments/events/systems`
  - `common/byDirection` 分桶
  - `DisplaySegment` 与边界 `DisplaySegmentBoundary`
  - 自动生成 transfer 事件（无显式 transfer 时）
  - `transferMode` 自动推断（`in_vehicle_through` / `alight_transfer`）
- 局限：
  - 只在单 `TripSegment` + 单 `lineKey` 范围内构建 display model
  - 缺少跨线统一 run-level 事件序列
  - `event type` 开放字符串，缺约束与版本
  - 编组/解挂、车窗绝景、用户创建事件尚无固定事件层级
  - 用户事件尚未表达为“与车辆运行相对绑定、但不参与寻路”的独立语义层

### 1.5 路由与时间估算
- 路由：`src/core/railwayRouting.ts#findRoute`
- 时间：速度估算 + transfer penalty，返回 `estimatedTime`
- 局限：
  - 时间语义是“估算分钟”，不是显式 timeline
  - 无“顺序点 + 锚点时刻 + 插值”统一模型

## 2. 与目标能力的对比

| 目标能力 | 当前状态 | 缺口 |
|---|---|---|
| 统一多层图（站台/站线/道岔/复线/桥隧） | 部分仅以 GeoJSON 标签存在 | 缺独立图实体、面/线/点/区间层级关系 |
| 上下行+复线路径自动/指定决策 | 仅 segment 级方向切片 | 缺 run 级路径决策引擎 |
| 事件层完整顺序与时间戳能力 | 有 boundary event 兼容 | 缺统一事件时间轴与跨线事件链 |
| 顺序优先+可选时刻表 | 仅 estimatedTime | 缺 timeline schema 与插值策略 |
| ORM 不一致/缺失自动补全 | 存在分散 fallback | 缺标准化补全规则与诊断分级 |
| 严格 TS 文件级接口体系 | 现有核心含 JS/any | 缺强类型模块边界 |
| 复线真实几何/动态偏移并存 | 方向线与回退几何混用 | 缺至少其一的硬约束与偏移平滑计划 |
| 车窗绝景与用户事件 | 尚无核心模型 | 缺地图方向到车窗侧转换、额外事件层与编辑输出 |

## 3. 可复用资产（后续设计必须继承）
- `networkMeta` 兼容语义（`common/byDirection/subSegments/events/systems`）
- `loopVia` 与 `computeLoopVia` 方向决策习惯
- worker 的几何回退链路
- TripSegment 语义：`lineKey/fromId/toId/loopVia`
- GeoJSON 自定义字段入口，可作为 `07` 契约的 adapter 输入来源

## 4. 明确边界结论
- 现有系统已经有“兼容层雏形”，但尚不是“统一对象系统”。
- 下一代设计必须把“输入几何、图拓扑、运行路径、渲染几何计划、时间、事件、补全诊断、编辑输出”解耦为可组合模块，并保持对旧数据兼容输入。
