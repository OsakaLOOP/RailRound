# 架构兼容性推理与调整建议

## 1. 结论

现有 `00-06` 的统一多层图、顺序优先时间轴、事件流、诊断与 patch 方向，与 `06` 新增约束总体兼容，但必须做四类调整：

1. 把 GeoJSON 输入从“泛 feature 标签”提升为明确的 `kind + geometry + 标准化实体` 契约。
2. 在图结构中加入 `areas`、`sections`、`eventLayer` 与 `renderGeometryPlan`，避免站台面、桥隧区间、车窗绝景被塞进普通 node/edge。
3. 把复线拆成可并存的 `physical_edges` 与 `dynamic_offset` 两种几何来源，要求至少具备其一，并将路径顺序与渲染几何分离。
4. 把编辑输出从“patch 可用”提升为硬性主接口：所有自动补全、人工修正、用户事件都必须能 snapshot/preview/apply/export。

## 2. 对 `06` 新增约束的逐条推理

### 2.1 站台是面对象，且需要绑定站线语义

兼容性：原统一多层图方向可兼容，但 `NormalizedEntityBatch` 只有 `nodes/edges/relations` 不足以表达面对象。

调整：

- 新增 `areas[]`，站台进入 `InfraArea(kind=platform)`。
- 用 `platform_serves_track` relation 绑定站台与站线/股道。
- `events.ts` 生成停靠/通过事件时，不直接读取面几何，而读取站台与运行 edge 的 relation。

### 2.2 站线/股道是线路 MultiLineString 的部分，可能需要提取与渲染拼接

兼容性：原 `GraphEdge` 可承载边，但必须补充“源几何切片”和“渲染拼接计划”。

调整：

- `normalizers.ts` 将 `MultiLineString` 拆成可寻址 edge。
- `relations[]` 记录 `source_geometry_slice`。
- `RenderGeometryPlan` 负责拼接和偏移，不改变路径唯一真源。

### 2.3 道岔是点对象

兼容性：原 `GraphNode` 可直接承载。

调整：

- `SwitchPoint` 必须进入 `InfraNode(kind=switch)`。
- `graph-builder.ts` 必须支持线内投影切分，将道岔点吸附到 edge adjacency。
- `events.ts` 通过 adjacency 与运行 edge sequence 生成 `switch_pass`。

### 2.4 复线结构必须覆盖物理数据与动态垂直偏移

兼容性：原服务层提到复线路径，但没有区分真实几何和渲染派生，也没有规定二者缺一时如何保证可运行。

调整：

- 新增 `DoubleTrackRelation.geometryModes[]`：
  - `physical_edges`：真实上下行 edge。
  - `dynamic_offset`：共享几何 + 方向服务边 + 渲染偏移。
- `geometryModes[]` 至少包含一项，二者可同时存在。
- `path-resolver.ts` 只选择服务 edge。
- `render-geometry.ts` 输出 `RenderGeometryPlan`，供后续渲染验证偏移策略。
- 动态偏移必须包含平滑连接策略，处理并线、分线、道岔、桥隧出入口的过渡。

### 2.5 存车线通常不直接经由，但有特殊意义

兼容性：原图层可兼容，但自动路径选择需要显式排除规则。

调整：

- `track.role=storage` 默认 `serviceable=false`。
- `path-resolver.ts` 默认不把存车线列入普通候选。
- 编组/解挂/折返等事件或 manual override 可引用存车线。

### 2.6 桥隧上下行分离需要明确命名和语义

兼容性：原“特殊区间”概念可兼容，但命名太粗。

调整：

- `SpecialSection.category` 表达桥/隧/高架等物理类别。
- `SpecialSection.directionSeparation` 表达上下行是否分离。
- 事件类型统一为 `special_section_pass`，payload 保留物理类别与分离方式。

### 2.7 新增固定事件：编组解挂作业

兼容性：原事件系统可扩展，但固定枚举缺项。

调整：

- 增加 `coupling_operation`、`decoupling_operation`。
- 这类事件可绑定站台、存车线、道岔区、站场节点，不要求一定在普通客运 path 主线上。

### 2.8 新增“车窗绝景”

兼容性：原事件模型可承载 payload，但锚定模式需要强类型。

调整：

- 增加 `scenic_view` 事件类型。
- 支持 `directional_view` 与 `fixed_map_point` 两种 anchor。
- `directional_view` 可输入地图绝对方向，并在事件锚点解析阶段转换为运行车窗侧与相对方向。
- 事件生成可来自输入 anchor、手工 patch 或后续用户创建，不影响路径拓扑。

### 2.9 后续支持应用中用户创建的其他事件，基础必须有

兼容性：原开放字符串事件有兼容性，但缺少可控扩展边界。

调整：

- 使用固定 `user_defined` 类型承载用户事件。
- `payload.eventKey` 表达用户定义子类型。
- `customData` 允许扩展，但不能影响核心不变量。
- 用户事件作为额外事件层级，只在时空语义上与车辆运行相对绑定，永不参与寻路。

### 2.10 编辑输出接口是硬要求

兼容性：原 `patch.ts` 已有方向，但调试接口与数据流没有把它放到主链。

调整：

- 主链扩展为 `SourceInput -> ... -> EventStream -> EditableSnapshot -> PatchSet -> Diagnostics`。
- `debug.ts` 必须输出 `EditableRailGraphSnapshot`。
- `patch.ts` 必须支持图实体、几何、关系、事件 anchor、事件 policy 的增改。

## 3. 对现有文档的必要改动

### 3.1 `02-设计约束与不变量.md`

需要加入：

- GeoJSON 几何类型约束。
- 面/线/点/区间分层不变量。
- 复线物理/动态偏移不变量。
- 编辑输出不变量。
- 事件层固定类型扩展。

### 3.2 `03-TS文件级蓝图.md`

需要加入：

- `geojson-contracts.ts` 或在 `contracts.ts` 中明确 GeoJSON 契约。
- `render-geometry.ts` 负责拼接和动态偏移计划。
- `event-anchors.ts` 负责车窗绝景方向转换与用户事件相对绑定。
- `editing.ts` 或强化 `patch.ts/debug.ts`，使编辑输出成为主接口。
- `types.ts` 补充 `InfraArea/SpecialSection/EventAnchor/RenderGeometryPlan`。

### 3.3 `04-核心数据流与运行核心数据.md`

需要加入：

- `areas[]/sections[]/eventAnchors[]`。
- `RenderGeometryPlan`。
- `EventAnchorResolution`。
- `EditableSnapshot/PatchSet`。

### 3.4 `05-测试与验收映射.md`

需要加入：

- GeoJSON geometry 与 kind 校验。
- MultiLineString 拆分与拼接计划。
- 复线 `physical_edges/dynamic_offset` 两套场景。
- 动态偏移平滑连接场景。
- 车窗绝景两种 anchor。
- 地图方向到运行车窗侧转换。
- 编组/解挂与用户事件。
- 用户事件不参与寻路。
- patch preview/apply/export 快照。

## 4. 保持兼容的关键边界

- legacy `networkMeta` 仍作为服务语义输入，不升级为物理拓扑真源。
- 现有 `loopVia` 仍是 `RunSpec.directionHint/pathOverride` 的用户意图来源。
- 现有 GeoJSON 自定义字段可由 adapter 映射为 `railGraph.kind`，但新契约内不继续扩散弱类型字段。
- 渲染偏移只属于 `RenderGeometryPlan`，不改变真实 `InfraEdge.geometry`。
- 道岔等点的吸附是底层构建/运行时逻辑，不要求输入数据提前固化连接结果。
- 用户事件不参与 `path-resolver.ts`，只在 `event-anchors.ts/events.ts` 中绑定运行时空语义。

## 5. 已拍板设计口径

- 动态偏移与具体物理数据同时兼容；复线必须至少具备其一。
- 动态偏移需要考虑平滑连接。
- 道岔等点的吸附是底层逻辑，可以动态计算。
- 车窗绝景必须能从地图方向转化为运行车窗侧和方向。
- 用户事件是额外事件层级，不影响寻路，只在时空语义上与车辆运行相对绑定。
