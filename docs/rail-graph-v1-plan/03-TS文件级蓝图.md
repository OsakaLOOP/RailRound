## 2. 文件级职责与接口

### 2.1 `types.ts`
- 职责：定义核心领域类型（唯一真源）。
- 导出结构：
  - `RailEntityId`
  - `RailGraph`
  - `GraphNode`, `GraphEdge`, `GraphRelation`
  - `InfraNode`, `InfraEdge`, `InfraArea`, `SpecialSection`
  - `DoubleTrackRelation`, `RenderGeometryPlan`
  - `RunSpec`, `RunPlan`, `RunPath`, `RunPathResult`
  - `RunEvent`, `TimelinePoint`, `EventAnchor`, `EventPolicy`, `EventPolicyRef`
  - `OffsetSmoothingPlan`, `OffsetGeometrySegment`
  - `PatchSet`, `PatchOp`, `EditableRailGraphSnapshot`
  - `Diagnostic`, `DiagnosticLevel`
- 约束：仅类型，无实现函数。

### 2.2 `ids.ts`
- 职责：稳定 ID 生成与校验。
- 方法：
  - `buildStableId(input: StableIdInput): RailEntityId`
  - `parseStableId(id: RailEntityId): ParsedStableId`
  - `assertStableId(id: string): void`
- 输入：源命名空间、实体类型、稳定字段。
- 输出：符合规范的稳定 ID。

### 2.3 `contracts.ts`
- 职责：输入输出契约定义（schema 层，不绑定具体源）。
- 结构：
  - `SourceBatchInput`
  - `NormalizedEntityBatch`
  - `BuildGraphOptions`
  - `ResolveRunOptions`
  - `BuildRunPlanOptions`
- 方法：
  - `validateSourceBatch(input): ValidationResult`
- 约束：引用 `geojson-contracts.ts` 的 GeoJSON 输入类型，但不直接解析 GeoJSON geometry。

### 2.4 `geojson-contracts.ts`
- 职责：定义 `07` 中的 GeoJSON feature kind、geometry 组合与 properties 强类型。
- 导出结构：
  - `RailGraphGeoJsonInput`
  - `RailGraphFeatureProperties`
  - `PlatformAreaProperties`
  - `TrackGeometryProperties`
  - `SwitchPointProperties`
  - `SpecialSectionProperties`
- 方法：
  - `validateRailGraphFeature(feature): ValidationResult`
  - `detectLegacyGeoJsonKind(feature): RailGraphGeoJsonKind | undefined`
- 约束：只处理输入契约与兼容检测，不构建图。

### 2.5 `normalizers.ts`
- 职责：将多源数据标准化为统一实体。
- 方法：
  - `normalizeSources(input: SourceBatchInput): NormalizedEntityBatch`
  - `normalizeNode(raw): GraphNode`
  - `normalizeEdge(raw): GraphEdge`
  - `normalizeArea(raw): InfraArea`
  - `normalizeSpecialSection(raw): SpecialSection`
  - `normalizeEventAnchor(raw): EventAnchor`
- 行为：处理缺字段默认值，记录诊断，不中断主流程；`MultiLineString` 必须拆为可寻址 edge 或 edge slice。

### 2.6 `graph-builder.ts`
- 职责：构建统一多层图。
- 方法：
  - `buildRailGraph(batch: NormalizedEntityBatch, options?): BuildGraphResult`
  - `linkInfraAndServiceLayers(graph): RailGraph`
  - `linkAreasAndTracks(graph): RailGraph`
  - `attachDynamicPoints(graph, options?): PointAttachmentResult`
  - `validateConnectivity(graph): Diagnostic[]`
- 输出：`RailGraph + diagnostics`。
- 行为：道岔等点到线的吸附在这里动态计算，结果进入 adjacency 与诊断。

### 2.7 `path-resolver.ts`
- 职责：生成运行路径顺序（支持自动和指定）。
- 方法：
  - `resolveRunPath(graph: RailGraph, spec: RunSpec, options?): RunPathResult`
  - `scoreCandidatePaths(candidates, context): PathScore[]`
  - `applyManualPathOverride(base, override): RunPath`
- 核心：输出可解释的路径选择理由。
- 约束：用户事件不参与寻路；存车线默认不进入普通候选。
- 附：`RunPathResult = { path: RunPath; diagnostics: Diagnostic[] }`

### 2.8 `render-geometry.ts`
- 职责：从 `RunPath` 生成渲染几何计划，不反写拓扑真源。
- 方法：
  - `buildRenderGeometryPlan(graph: RailGraph, path: RunPath, options?): RenderGeometryPlan`
  - `buildDynamicOffsetPlan(relation: DoubleTrackRelation, context): OffsetGeometryPlan`
  - `smoothOffsetTransitions(plan: OffsetGeometryPlan, options?): OffsetGeometryPlan`
  - `stitchEdgeGeometries(edgeRefs, graph): StitchedGeometry`
- 行为：物理 edge 与动态偏移可同时存在；动态偏移必须考虑平滑连接。

### 2.9 `timeline.ts`
- 职责：顺序优先时间轴生成。
- 方法：
  - `buildRunOrder(path: RunPath): RunOrder`
  - `synthesizeTimeline(order: RunOrder, anchors?): TimelineResult`
  - `interpolateIntermediateTimes(points, strategy): TimelinePoint[]`
- 行为：锚点优先，缺失中间时刻自动插值并标注。

### 2.10 `events.ts`
- 职责：事件投影与事件流生成。
- 方法：
  - `generateRunEvents(graph, runPath, timeline, options?): EventResult`
  - `projectStationEvents(runPath, timeline, eventPolicy?, graph): PlatformEvent[]`
  - `projectJunctionEvents(runPath, timeline, graph): SwitchPassEvent[]`
  - `projectSpecialSectionEvents(runPath, timeline, graph): SpecialSectionEvent[]`
  - `projectSystemSwitchEvents(runPath, graph): SystemChangeEvent[]`
  - `projectOperationEvents(runPath, timeline, graph): OperationEvent[]`
  - `projectScenicViewEvents(resolvedAnchors, timeline): ScenicViewEvent[]`
  - `projectUserDefinedEvents(boundEvents, timeline): UserDefinedEvent[]`
  - `inferTransferMode(leftSegment, rightSegment, graph): TransferMode`
- 输出：有序 `RunEvent[]`，每条事件可追溯来源。
- 约束：用户事件作为事件附加层投影到 order/time/entity/geometry anchor，不影响 `path-resolver.ts`。
- 附：`EventResult = { events: RunEvent[]; diagnostics: Diagnostic[] }`

### 2.11 `event-anchors.ts`
- 职责：事件锚点解析、车窗绝景方向转换、用户事件相对绑定。
- 方法：
  - `resolveEventAnchors(graph, path, anchors): ResolvedEventAnchor[]`
  - `resolveScenicView(anchor, runContext): ScenicViewResolution`
  - `mapBearingToVehicleView(mapBearingDegrees, runDirectionBearingDegrees): VehicleViewDirection`
  - `bindUserEventToRun(anchor, order, timeline): BoundUserEvent`
- 行为：地图绝对方向可转换为运行车窗侧与相对方向。

### 2.12 `enrichment.ts`
- 职责：缺失数据补全与语义推断。
- 方法：
  - `enrichGraph(graph, context): EnrichResult`
  - `inferDirectionForEdge(edge, context): DirectionInference`
  - `fillMissingPlatformRefs(node, context): Patch[]`
  - `inferDoubleTrackRelation(edges, options?: { hausdorffM?: number; angleDeg?: number; overlapRatio?: number }): DoubleTrackRelationInference`
    - 默认阈值：hausdorffM=50, angleDeg=15, overlapRatio=0.6
  - `createSyntheticOffsetRelation(edge, context): Patch[]`
- 行为：补全必须伴随诊断。

### 2.13 `diagnostics.ts`
- 职责：统一诊断模型与聚合。
- 方法：
  - `createDiagnostic(level, code, message, context): Diagnostic`
  - `collectDiagnostics(...groups): Diagnostic[]`
  - `hasFatalDiagnostics(list): boolean`

### 2.14 `patch.ts`
- 职责：支持随时增改（手工修补/自动修补统一入口）。
- 方法：
  - `applyGraphPatch(graph, ops): PatchResult`
  - `previewGraphPatch(graph, ops): PatchPreview`
- 结构：`PatchOp` 支持 add/update/remove/link/replace_geometry/add_event_anchor/update_event_policy。
- 约束：patch 不直接修改原始 GeoJSON/ORM 输入，只作用于标准化 JSON 或 graph snapshot。

### 2.15 `editing.ts`
- 职责：编辑输出主接口，组合 patch、snapshot、诊断和回放。
- 方法：
  - `createEditableSnapshot(graph, runPlans?, diagnostics?): EditableRailGraphSnapshot`
  - `previewPatchSet(snapshot, patchSet): PatchPreview`
  - `applyPatchSet(snapshot, patchSet): EditableRailGraphSnapshot`
  - `exportPatchSet(patchSet): string`
- 行为：自动补全、人工修正、事件锚点新增都必须可预览、可应用、可导出。

### 2.16 `adapters/legacy-network-meta.ts`
- 职责：兼容旧 `networkMeta` 输入。
- 方法：
  - `adaptLegacyNetworkMeta(rawMeta, lineContext): AdaptedServiceSemantics`
- 覆盖：`common/byDirection/subSegments/events/systems` 全语义。

### 2.17 `adapters/orm-input.ts`
- 职责：ORM 数据转标准输入。
- 方法：
  - `adaptOrmRecords(records): SourceBatchInput`
  - `mapOrmStations(...)`
  - `mapOrmTracks(...)`
- 核心字段映射（参考）:
  - `orm.station_name` → `InfraNode.name`
  - `orm.station_id` → `InfraNode.id` (外部源 ID)
  - `orm.track_code` → `InfraEdge.track.trackCode`
  - `orm.line_id` → `InfraEdge.track.lineRef`
  - `orm.direction` (0/1) → `InfraEdge.track.direction` ("up"/"down")
  - `orm.is_storage` → `InfraEdge.track.role = "storage"`

### 2.18 `adapters/openrailwaymap-input.ts`
- 职责：OpenRailwayMap 对象转标准输入。
- 方法：
  - `adaptOpenRailwayMapObjects(objects): SourceBatchInput`
  - `extractPlatformTrackSwitchBridgeTunnel(...)`
  - `extractDoubleTrackRelations(...)`
  - `extractEventAnchors(...)`
- 核心标签 → kind 映射（参考）:
  - `railway=platform` + `public_transport=platform` → `platform_area`
  - `railway=rail` + `usage=main/branch` → `track_geometry` (role=main/branch)
  - `railway=rail` + `usage=siding` + `service=yard` → `track_geometry` (role=storage)
  - `railway=switch` → `switch_point`
  - `railway=rail` + `bridge=yes` → `special_section` (category=bridge)
  - `railway=rail` + `tunnel=yes` → `special_section` (category=tunnel)
  - `railway=rail` + `tracks=2` (双线) → 触发 `extractDoubleTrackRelations`

### 2.19 `debug.ts`
- 职责：前期调试接口与快照导出。
- 方法：
  - `buildGraphSnapshot(input, options?): GraphSnapshot`
  - `buildRunPlanSnapshot(graph, runSpec): RunPlanSnapshot`
  - `buildEditableRailGraphSnapshot(input, runSpecs?, options?): EditableRailGraphSnapshot`
  - `exportDiagnosticsReport(diags): DiagnosticsReport`

### 2.20 `index.ts`
- 职责：统一公共导出入口。
- 导出：
  - 类型导出（`types.ts`）
  - 主流程函数：`normalizeSources/buildRailGraph/resolveRunPath/buildRenderGeometryPlan/synthesizeTimeline/generateRunEvents/applyGraphPatch/createEditableSnapshot`

## 3. 主流程级接口（实现必须保留）

### 3.1 图构建入口
- `buildRailGraphPipeline(input: SourceBatchInput, options?): BuildRailGraphPipelineResult`
- 返回：
  - `graph: RailGraph`
  - `diagnostics: Diagnostic[]`
  - `stats: { nodeCount; edgeCount; layerCounts }`

### 3.2 运行计划入口
- `buildRunPlan(graph: RailGraph, spec: RunSpec, options?): BuildRunPlanResult`
- 返回：
  - `runPath: RunPath`
  - `renderGeometryPlan: RenderGeometryPlan`
  - `timeline: TimelinePoint[]`
  - `events: RunEvent[]`
  - `diagnostics: Diagnostic[]`

### 3.3 编辑输出入口
- `buildEditableSnapshot(input: SourceBatchInput, specs?: RunSpec[], options?): EditableRailGraphSnapshot`
- 返回：
  - `graph: RailGraph`
  - `runPlans: RunPlanSnapshot[]`
  - `pendingPatches: PatchSet[]`
  - `diagnostics: Diagnostic[]`

## 4. 文件间依赖规则
- `types.ts` 不依赖任何业务文件。
- `index.ts` 只聚合导出，不写业务逻辑。
- `adapters/*` 只能依赖 `types/contracts/geojson-contracts/ids/diagnostics`，不得反向依赖 UI 层。
- `events/timeline/path-resolver/render-geometry` 依赖 `graph-builder` 产物，不直接消费原始输入。
- `event-anchors.ts` 可被 `events.ts` 调用，但不得调用 `path-resolver.ts`。

## 5. 实现期禁区
- 不在核心模块直接读 Zustand store。
- 不在核心模块直接操作 DOM 或 worker 端口。
- 不在核心模块引入 UI i18n 文案。
