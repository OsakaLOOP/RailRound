# 测试与验收映射

## 1. 测试目标
本文件定义实现阶段的测试范围与验收口径，确保新对象系统满足：
- 结构完备
- 行为可解释
- 缺失可补全
- 兼容可落地

## 2. 模块到测试映射

### 2.1 `ids.ts`
- 用例：
  - 同输入生成同 ID（幂等）
  - 缺失源 ID 时 fallback 稳定
  - 非法 ID 格式校验
- 验收：无随机漂移 ID。

### 2.2 `normalizers.ts` + `contracts.ts`
- 用例：
  - 多源混合输入标准化
  - 缺字段默认补全
  - 非法字段记录诊断
- 验收：输出结构完整，诊断可追溯。

### 2.3 `graph-builder.ts`
- 用例：
  - 站台/股道/道岔/桥隧/复线实体建图
  - 层间关联正确建立
  - 断裂图检测
- 验收：图索引一致，连通性检查可用。

### 2.4 `path-resolver.ts`
- 用例：
  - 自动路径选择
  - 手动 override 覆盖
  - 上下行/复线候选评分解释
- 验收：同输入路径稳定，可输出评分理由。

### 2.5 `timeline.ts`
- 用例：
  - 仅顺序生成时间点
  - 部分锚点插值
  - 冲突锚点修正
- 验收：时间单调，插值点标记 `isSynthesized`。

### 2.6 `events.ts`
- 用例：
  - 停靠/跨越站台事件
  - 道岔事件
  - 特殊区间事件
  - 系统切换事件
  - 跨线与同车直通边界事件
- 验收：事件有序、可追溯、可选带时间戳。

### 2.7 `enrichment.ts` + `diagnostics.ts`
- 用例：
  - 缺失字段自动补全
  - 不同级别诊断聚合
  - fatal 阻断流程
- 验收：补全不静默，fatal 行为可预测。

### 2.8 `patch.ts`
- 用例：
  - add/update/remove/link patch
  - preview 与 apply 一致
- 验收：patch 不破坏稳定 ID 与图一致性。

### 2.9 `adapters/*`
- 用例：
  - legacy networkMeta 映射完整
  - ORM 输入映射
  - OpenRailwayMap 输入映射
- 验收：兼容层语义不丢失。

## 3. 场景级验收

### 3.1 复合线路场景
- 包含：复线、上下行分离、桥隧分离、存车线、道岔。
- 验收：路径可唯一确定，事件链正确。

### 3.2 跨线运行场景
- 包含：跨线后系统/车种/服务别变更。
- 验收：边界事件完整，transferMode/requiresTransfer 可解释。

### 3.3 缺失与冲突场景
- 包含：字段缺失、方向冲突、局部断裂。
- 验收：流程尽可能继续，诊断准确分级。

## 4. 回归兼容验收
- 对照现有 `networkDisplay` 行为，验证：
  - `subSegments/events/systems`
  - `common/byDirection`
  - 自动 transfer 补全
- 验收：兼容输入在新系统下不退化。

## 5. 最终通过标准
以下全部满足视为通过：
1. 核心主链可闭环跑通（离线）。
2. 所有关键模块有对应测试与明确断言。
3. 关键场景输出结果可人工审阅且可复现。
4. 无 `fatal` 时可稳定产出 `RunPath + Timeline + EventStream`。
